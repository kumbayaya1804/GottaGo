## Typography

Source: `design-system.md §2`. All `fontSize` values in StyleSheet MUST reference `typography.ts` constants — no inline raw numbers. The 9-level scale applies in full. Phase 2 uses the following 4-size subset with exactly 2 weights:

| Role | Token | Size | Weight | Line Height | Phase 2 Usage |
|------|-------|------|--------|-------------|---------------|
| Display | `typography.display` | 34pt | SemiBold 600 | 41pt | Welcome Screen: "Gotta Go" app name |
| H2 | `typography.h2` | 22pt | SemiBold 600 | 28pt | Screen titles: "Sign In", "Create Account", "Enable Location", "Profile"; modal titles: "Delete Account" |
| H3 / Body / BodyMedium | `typography.h3` / `typography.body` / `typography.bodyMedium` | 17pt | SemiBold 600 (H3, button labels) / Regular 400 (body copy, placeholders) | 22pt (H3) / 24pt (Body/BodyMedium) | H3: Settings section headers ("Stats", "Settings"), Auth Required modal heading. Body: form field placeholders, body copy on GPS Consent, Profile stats values. BodyMedium (button labels): all Primary and Secondary button labels — SemiBold 600 at 17pt. |
| Subhead | `typography.subhead` | 15pt | Regular 400 | 20pt | TOS/Privacy copy below Create Account button; masked email in Profile; metadata rows in Settings; "Forgot password?" link |

**Phase 2 declared weights: Regular 400 and SemiBold 600 only.**
- Regular 400: Body, Subhead, form field placeholders, secondary text
- SemiBold 600: Display, H2, H3 section headers, all button labels (Primary, Secondary, Destructive, Ghost)

**Sizes not used in Phase 2 screens:**
- Caption (13pt, `typography.caption`) — exists in `typography.ts` for Phase 3+ use (timestamps, distance metadata). No Phase 2 screen renders 13pt caption text.
- Label (11pt, `typography.label`) — exists in `typography.ts` for Phase 3+ use. The tab bar label (11pt) is configured via Expo Router's tab bar `tabBarLabelStyle` prop, not via component-level typography constants. No Phase 2 component directly renders 11pt text.
- Bold 700 and Medium 500 weights — exist in `typography.ts` constants for Phase 3+ use. Phase 2 component StyleSheets must not use these weights.

Dynamic type tolerance: all layouts use flex-based sizing. `numberOfLines` is forbidden on screen title, CTA labels, error copy, and display name. It is permitted on the tagline below the logo if a hard truncation is acceptable at extreme type sizes (confirm in implementation).

### Screen 4: GPS Consent Screen

**Route:** Root overlay (fullscreen, no tab bar) — shown after sign-in/sign-up on first launch only
**Wireframe:** `docs/design/wireframes.md` — "GPS Consent Pre-prompt"

#### Layout

```
[spacing.lg = 20pt]

  "Gotta Go uses your location to find bathrooms nearby.
   We never share your exact location or store your GPS history."
[flex spacer]
[Primary button: "Enable Location" — full width, 56pt height, spacing.base margin]
[spacing.lg = 20pt]
[Ghost link: "Skip for now" — centered, colors.textSecondary, Body typography]
[spacing.xl = 24pt]
```

#### State Machine

| State | What Happened | What's Shown | Next |
|-------|--------------|-------------|------|
| Shown (first launch only) | User just signed in/up; `gps_consent` is false | Full screen explanation + "Enable Location" + "Skip for now" | User taps button |
| OS Dialog Open | User tapped "Enable Location" | OS system dialog overlays screen | User grants/denies |
| Granted | OS dialog → granted | Write `gps_consent = true`, `gps_consent_at = now()` via SECURITY DEFINER RPC | Navigate to `/(tabs)/index` |
| Denied | OS dialog → denied | `gps_consent` stays false, no write | Navigate to `/(tabs)/index` in ERR-01 (manual search) state |
| Skipped | User tapped "Skip for now" | `gps_consent` stays false, no write | Navigate to `/(tabs)/index` in ERR-01 state |
| Not shown (returning user) | `gps_consent` already set (true or false) | Screen never appears | Direct to `/(tabs)/index` |

**GPS Consent Write Rule (non-negotiable, from design-system.md §16):**
The "Enable Location" button triggers `Location.requestForegroundPermissionsAsync()` ONLY — it is NOT itself consent. `gps_consent = true` is written ONLY after the OS dialog resolves to `granted`. Writing before OS resolution records false consent and violates GDPR.

Re-prompt policy: GPS Consent screen is shown exactly once (first launch after sign-in). Re-prompting is only possible from Settings → Location Permissions. Never automatically re-shown.

#### Interactions

| Trigger | Response |
|---------|----------|
| Tap "Enable Location" | Call `Location.requestForegroundPermissionsAsync()` to trigger OS dialog |
| OS dialog → granted | Call SECURITY DEFINER RPC to write consent; navigate to Map tab |
| OS dialog → denied | Navigate to Map tab in manual search mode (ERR-01) — no error shown on this screen |
| Tap "Skip for now" | Navigate to Map tab in manual search mode (ERR-01) |

#### Accessibility

| Element | accessibilityRole | accessibilityLabel | accessibilityHint |
|---------|-------------------|--------------------|------------------|
| Location icon | `image` (decorative) | `accessibilityElementsHidden={true}` | Not interactive |
| "Enable Location" button | `button` | "Enable Location" | "Opens the system dialog to grant location permission" |
| "Skip for now" | `button` | "Skip for now" | "Continue without location access. You can enable it later in Settings." |

#### Error States Applicable

- ERR-01 (GPS Denied): handled on Map tab after navigating away — not shown on this screen
- No dead-end state: both outcomes (grant and deny) lead to the Map tab

## Accessibility Requirements (Phase 2)

Source: `design-system.md §18`. These rules apply to all Phase 2 screens.

### Touch Targets

- All tappable elements: `minHeight: 44`, `minWidth: 44`
- Primary submit buttons: `minHeight: 56`
- Ghost/text buttons visually smaller than 44pt: `hitSlop: { top: 8, bottom: 8, left: 8, right: 8 }`

### Screen Reader

- Every form field: `accessibilityLabel` + associated visible label Text above the field
- Error containers: `accessibilityLiveRegion="assertive"` — screen reader announces errors without user navigation
- Destructive button: `accessibilityHint="This will permanently delete your account"`
- Disabled buttons: `accessibilityState={{ disabled: true }}`
- iOS: test with VoiceOver; Android: test with TalkBack

### Color Contrast

- All body text and UI copy: minimum 4.5:1 (WCAG AA)
- Auth buttons: `textInverse` (#FFFFFF) on `primary` (#1A73E8) = 4.6:1 — passes AA
- Error text: `errorRed` (#EA4335) on `background` (#FFFFFF) = 4.5:1 — passes AA
- Disabled text: `textDisabled` (#9AA0A6) on `background` (#FFFFFF) = 2.9:1 — exempt (disabled element)
- `textSecondary` (#5F6368) on `background` (#FFFFFF) = 5.9:1 — passes AA

### Non-Color-Only Status

Auth error states: inline `alert-circle` icon + error text (never color-only red border without text).

### Dynamic Type

- No `numberOfLines` on: screen titles, button labels, error copy, display name
- All layouts use flex-based sizing — no hardcoded row heights
- Test at iOS Larger Text +5 steps before sign-off

### Reduced Motion

- Sign-in/sign-up forms: no animations to configure in Phase 2
- Auth Required Modal slide-up: check `AccessibilityInfo.isReduceMotionEnabled()` — if true, modal appears instantly without spring animation
- Delete Account modal: same — instant appear without animation
