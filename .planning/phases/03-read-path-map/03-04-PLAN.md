<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Settings Switch → update_profile RPC | Authenticated write of a user preference; must not let the client bypass the server-side family_mode read used by search RPCs. |
| Nearby list → search RPCs | Renders already-filtered rows; must not re-implement moderation/family_mode filtering client-side. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-15 | Tampering / Info Disclosure | family_mode write | mitigate | Toggle only posts the boolean to the authenticated update_profile RPC (only new_family_mode, so display_name is preserved by 03-01's coalesce); search RPCs still derive family_mode server-side via auth.uid(), so a tampered client cannot reveal sensitive rows by lying about the toggle. |
| T-03-16 | Information Disclosure | user-scoped cache | mitigate | family_mode read + invalidation use the ['familyMode', session.user.id] key (Codex WU-02-T5); no cross-user leak. |
| T-03-17 | Information Disclosure | Nearby row render | mitigate | Rows render only public-safe fields from the RPC (no access code); client does not re-filter moderation. The sheet's distance is re-fetched server-side (get_location_detail), a scalar echo, not a client computation. |
| T-03-18 | Information Disclosure | a11y labels / logs | mitigate | accessibilityLabels contain name/distance/confidence only — no address/PII; no coords logged (CLAUDE.md). The current coords (from useCurrentPosition) are forwarded only to the RPCs, not logged. |
| T-03-SC | Tampering | package installs | mitigate | No new installs in this plan. |
</threat_model>
