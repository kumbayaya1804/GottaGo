## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon/authenticated client → PostgREST RPC | Untrusted client calls the three read RPCs and update_profile over HTTPS; JWT may be absent (anon) or present (authenticated). |
| RPC body → base tables | SECURITY DEFINER executes as owner, bypassing RLS — the RPC body is the sole enforcement point for moderation/family_mode/column exposure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | get_location_detail / bbox / nearby return shape | mitigate | Explicit public column list; never `setof locations`/`select l.*`; access_instructions omitted entirely (OQ-3); shadowban/deleted/suppressed columns never returned (Pitfall 4). |
| T-03-02 | Tampering / Info Disclosure | family_mode filter | mitigate | Read family_mode from `public.users` via `auth.uid()` server-side; never a client parameter (Pitfall 3). pgTAP asserts sensitive rows absent for family_mode user regardless of client input. |
| T-03-03 | Information Disclosure | moderation filter | mitigate | Four-clause `deleted_at/suppressed_at/shadowban_status` filter in every RPC body + RLS select policy updated for direct-table belt-and-suspenders. pgTAP asserts absence. |
| T-03-04 | Elevation of Privilege | SECURITY DEFINER search_path | mitigate | `set search_path = public` + schema-qualified refs on all four functions (Pattern 5). |
| T-03-05 | Tampering (SQL injection) | RPC numeric/uuid params | mitigate | Parameterized args only; no dynamic SQL string-building; bbox coords typed `numeric`, id typed `uuid` (CLAUDE.md: no raw SQL outside migrations). |
