<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client hook → Supabase RPC | Hooks send RPC args over HTTPS; the JWT (if any) rides the supabase client. Client must not supply family_mode (server derives it). |
| in-app cache → next signed-in user | An app-lifetime QueryClient can leak one user's cached data to the next signed-in user within the same process. |
| device GPS → useCurrentPosition | Live coordinates read from the OS; forwarded only to the get_location_detail/nearby RPCs over HTTPS, never logged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-08 | Information Disclosure | user-scoped query cache | mitigate | family_mode (and any user-scoped) query keys include `session?.user.id` + `enabled: session !== null` (Codex WU-02-T5); test asserts the key. |
| T-03-09 | Tampering | family_mode write path | mitigate | Client only posts `{ new_family_mode }` to update_profile (authenticated-only RPC); it never passes family_mode to read RPCs, so the server-side filter cannot be bypassed by the client. The family-mode-only write omits new_display_name and 03-01's coalesce leaves display_name intact. |
| T-03-10 | Information Disclosure | client types / mapping | mitigate | types.ts and the detail hook omit any access-code field; client never re-filters moderation (server-authoritative); distanceM is a scalar echoed from the server, not derived from raw coordinates client-side. |
| T-03-23 | Information Disclosure | useCurrentPosition coords | mitigate | Live coords held in memory only, forwarded to RPCs over HTTPS; no lat/lng logged (CLAUDE.md no-PII). Denied permission returns null (no coordinate leak / no throw). |
| T-03-SC | Tampering | npm installs (@gorhom/bottom-sheet, expo-localization) | mitigate | RESEARCH Package Legitimacy Audit rated both `[OK]` (long-lived / first-party, no postinstall); no `[ASSUMED]`/`[SUS]`/`[SLOP]` packages, so no blocking legitimacy checkpoint required. supercluster explicitly NOT installed. |
</threat_model>
