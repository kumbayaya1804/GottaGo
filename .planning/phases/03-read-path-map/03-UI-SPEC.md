## Spacing Scale

Declared values (established `spacing.ts` — all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon padding, micro gaps, pin-corner icon inset |
| sm | 8px | Label↔icon gap, chip internal padding, badge padding |
| md | 12px | Between list items (Nearby rows) |
| base | 16px | Standard horizontal screen margin, card/sheet padding |
| lg | 20px | Between card and next section inside sheet |
| xl | 24px | FAB safe-area inset, section gaps |
| xxl | 32px | Between major screen sections |
| xxxl | 48px | Full-screen modal top padding |
| giant | 64px | FAB / max touch-target dimension |

Exceptions: Touch targets ≥44pt minimum on all interactive elements (design-system.md §18.2). Emergency-mode elements ≥56pt — **not exercised in this phase** (Emergency Mode is Phase 8). FAB 64×64pt — the emergency FAB is Phase 8; Phase 3 does not add it.

**Accepted exception (D-33):** `md=12px` and `lg=20px` fall outside the standard {4,8,16,24,32,48,64} set flagged by gsd-ui-checker Dimension 5. Both are established Phase 1.5 tokens already shipped in Phase 1/2 screens — see `03-CONTEXT.md` D-33 for the user-approved rationale. Not a Phase 3 defect; not to be re-flagged.

## Color

60/30/10 split (light / dark token pairs from `Colors.ts`). Never reference raw hex in components — always `Colors[colorScheme].tokenName`.

| Role | Token (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `background` #FFFFFF / #121212 | Map canvas base, screen background, full-sheet surface |
| Secondary (30%) | `surface` #F8F9FA / #1E1E1E<br>`mapOverlay` rgba(255,255,255,0.92) / rgba(30,30,30,0.92) | Cards, LocationDetail sheet body, Nearby list rows, tab bar (`tabBackground` #FFFFFF / #1E1E1E), floating map-overlay controls |
| Accent (10%) | `primary` #1A73E8 / #8AB4F8 | See reserved-for list below |
| Destructive | `emergency` #D93025 / #F28B82 | Emergency/critical only — **NOT used in this phase** (Emergency Mode = Phase 8). No destructive action ships in Phase 3. |

**Accent (`primary`) reserved for — explicit list:**
- "Get Directions" primary button in LocationDetail action row
- "Search this area" button (empty/error states)
- Active/selected filter chip fill
- Selected tab-bar icon (`tabIconSelected`)
- Text links (`textLink`) — e.g. "Sign in to view the access code" on LocationDetail
- `family_mode` toggle ON state (Settings)
- Retry affordance text on the RPC-failure banner

**Semantic status colors (separate axis from 60/30/10 — encode data, not brand emphasis; every use pairs color WITH icon/text per §18.4, never color-only):**
- Map pin by policy tag: `pinChillSpot` #34A853, `pinCodeRequired` #EA8600, `pinPublicFacility` #4285F4, `pinPurchaseRequired` #767676. Cluster badge = dominant policy-tag color + count.
- Confidence badge pill: `confidenceHigh` #34A853, `confidenceMedium` #FBBC04 (text uses `textPrimary`, not white), `confidenceLow` #EA4335.
- Offline/network banner: `offlineBanner` #FFF3CD bg / `offlineBannerText` #664D03.
- Skeleton loaders: `skeletonBase` / `skeletonHighlight`.

Contrast: WCAG 2.1 AA baseline — 4.5:1 body text, 3:1 large text (design-system.md §18). `pinPurchaseRequired` gray and `confidenceMedium` amber require `textPrimary` (dark) text, never white.

## Component & Interaction Contract

Executor source-of-truth for the four Phase 3 surfaces. All must pass design-system.md §20 checklist.

### MapScreen (`(tabs)/index.tsx` — plans 03-02, 03-03)
- Mapbox `MapView` with light/dark style switching following OS theme (D-25). Map tile renders immediately; pins arrive async (no blocking spinner, D-02).
- Pins via `ShapeSource` + `SymbolLayer`, `cluster: true`; pin color driven by a Mapbox `match` expression on `policy_tag` (§20 map-pin rule — not React state). Wheelchair / changing-table icon overlays at pin corner (`xs` 4px inset).
- User-location "blue dot" via Mapbox built-in user-location layer, visually distinct from bathroom pins (D-26).
- Cluster badge: circular, dominant policy-tag color + count; tap → zoom to expand (design-system.md §14).
- Viewport auto-refetch `search_locations_bbox`, debounced 400ms after movement stops (D-01). Viewport persists within session; resets only on cold start (D-03).
- Beyond max zoom-out threshold: replace pins with "Zoom in to see individual locations" (D-04).
- Map canvas is visual-only — no per-pin screen-reader semantics required (D-27); Nearby tab is the accessible alternative.
- Filter chip row anchored to the top of the map screen (horizontal, scrollable): `[Changing Table] [Wheelchair] [Chill Spot] [Open Now] [Clean: 4+]`. **Narrowed 2026-07-05 (D-34):** no persistent search-bar component is built in Phase 3 — the denied-GPS state (ERR-01) has its own manual-search entry, not a shared always-present search bar. Active = `primary` fill. AND logic across selected chips (D-07). Null/missing underlying data → INCLUDED, never silently excluded (D-08). Filters persist within session (D-06), reset on cold start (D-05).

### LocationDetail bottom sheet (plan 03-02)
- Full peek(30%) / half(55%) / full(90%) sheet — build complete component now, not a placeholder (D-12). `@gorhom/bottom-sheet`, radius `md` 12px top corners.
- Peek: name (h2), distance (subhead), policy-tag badge, confidence badge.
- Half: hours (or "Hours not yet available"), accessibility flags, action row.
- Full: directions context. Ratings-summary & timing-tips sections HIDDEN entirely until Phase 4/8 (D-14) — not empty states.
- Action row order `[Get Directions] [GPS Verify] [Rate] [Report]`; only Get Directions renders this phase (D-13/D-20). Action row appears once first action ships.
- Dismiss via swipe-down or tap-outside scrim (`scrim` token) — no explicit close button (D-17).
- Multiple pin taps animate content in-place (no dismiss/reopen); map re-centers; snap point retained.
- On open: immediate peek + animated skeleton bars (`skeletonBase`/`skeletonHighlight`) → resolve <300ms.
- Access code: absent for anonymous users (ERR-11) — anonymous sees everything else (D-24). Reveal UX is Phase 8, out of scope here.

### Nearby list-view tab (`(tabs)/nearby.tsx` — plan 03-04, D-29)
- Sorted-by-distance list from the same `search_locations_bbox` / `search_locations_nearby` RPCs — accessible alternative to the map, NO Mapbox dependency.
- Row: name (body), policy-tag badge, distance + "Verified N days ago" (subhead), confidence badge. Tap row → LocationDetail (same sheet component) or `/location/[id]`.
- Full screen-reader semantics: `accessibilityRole`, `accessibilityLabel`, `accessibilityHint` on every row (§20 accessibility gate). Same empty / filtered-empty / error states as MapScreen.
- Row vertical rhythm: `md` 12px between items; horizontal margin `base` 16px.

### Settings — `family_mode` toggle (`(tabs)/profile.tsx` — plan 03-04, D-30)
- Add a single labeled switch to the existing Settings list. Label: "Family mode". Helper text (caption, `textSecondary`): "Hide locations flagged as sensitive from all searches."
- ON state uses `primary` accent (native `Switch` track). Non-destructive — no confirmation dialog.
- Authenticated-only (write path extends existing `update_profile` RPC with optional `family_mode` param). Read must use user-id-scoped TanStack Query `queryKey` (Phase 2 cross-user cache-leak guard, Codex WU-02-T5). `accessibilityRole="switch"`, `accessibilityState={{ checked }}`.
