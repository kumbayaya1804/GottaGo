<objective>
Evolve the event model so pre-publication verification can be represented, and give a second independent user a proximity-bounded path to discover pending submissions.

Purpose: Everything downstream (weight, atomic publish, trust, notifications) depends on an auditable, immutable, uniqueness-guaranteed verification-event model and a way for verifiers to find candidates. This plan lays that foundation without changing weight/publish logic (that is 05-02).

Output: `phase5_event_model` migration (polymorphic FK, exactly-one CHECK, uniqueness index, `submission_tags` staging table, `submissions.status` lifecycle CHECK adding `cancelled`, weight-input columns, preserved lockdown), `phase5_discovery_rpc` migration (`search_pending_submissions_nearby` + partial GiST index), two pgTAP suites, and regenerated `database.types.ts`.
</objective>
