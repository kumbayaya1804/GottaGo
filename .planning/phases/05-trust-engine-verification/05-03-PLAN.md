## Copy contract (from 05-UI-SPEC.md — LOCKED strings verbatim)
- Modal title: "Verify Location"; Primary CTA: "I'm Here" (56pt, primary; enabled only when accuracy ≤50m AND within 100m).
- GPS readout good: "Accuracy: {N}m ✓" + "You are {N}m away" (successGreen). GPS readout poor: "GPS accuracy too low — move to an open area and try again." (warningAmber, button disabled).
- Server rejection (ANY reason, ERR-09): "Unable to verify your location. Please try again." — the ONLY rejection string.
- Permission denied: "Location access is off. Turn on location so we can confirm you're here." (offers settings/dismiss, not a dead end).
- Success: heading "Verified!" + body "Thanks for keeping data fresh." + dismiss "Done".
- Discovery heading: "Verify a bathroom nearby". Empty: "Nothing to verify nearby" / "There are no pending bathrooms within walking distance right now. When you're near a newly submitted spot, it'll show up here to verify."
- Published! resolution: heading "Published!" + body "Your bathroom is now live on the map. Thanks for helping people find a place to go."

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| VerifyFlow → verify_location RPC | Client renders server results; must never surface the specific rejection reason back to the user |
| device GPS → client advisory | Client-side readout is advisory UX only; it calls no server and leaks nothing |
| app-lifetime QueryClient → account switch | User-scoped cached data must not survive a sign-out/account switch into the next account |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-13 | Information Disclosure | rejection-reason leakage in UI | mitigate | Wizard maps ANY error to the single ERR-09 string; no per-reason branch (SC7); jest asserts all reasons render identical copy |
| T-05-14 | Denial of Service (UX) | dead-end permission/error states | mitigate | Denied + rejected states always offer a recovery affordance; no dead ends (UI-SPEC §17.2) |
| T-05-15 | Information Disclosure | candidate list exposing identity/secret | accept | Server (05-01) already strips submitter identity/secrets; client renders only safe columns — no new surface here |
| T-05-26 | Information Disclosure | cross-account query-cache leak on shared device | mitigate | Every user-scoped query namespaces its queryKey by user id + `enabled: !!userId` (Phase 2 standing rule); jest account-switch test proves no leak |
</threat_model>
