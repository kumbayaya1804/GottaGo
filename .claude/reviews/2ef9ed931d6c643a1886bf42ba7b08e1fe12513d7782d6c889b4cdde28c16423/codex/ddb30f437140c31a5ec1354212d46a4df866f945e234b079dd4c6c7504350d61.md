### Findings

1. **C5, high — reopening after a failed discovery can falsely report an empty area.** `app/src/features/verify/useVerifyCandidates.ts:68-78` sets `retry: false` but leaves TanStack Query's `retryOnMount` enabled. If discovery reaches the server and its response is lost, closing and reopening Verify within three seconds immediately mounts an errored query with no data and calls discovery again. The manual Retry wait in `app/src/app/(modals)/verify.tsx:150-170` is bypassed. The server advances `last_discovery_at` on every call and answers the second call with zero rows (`supabase/migrations/20260717120100_phase5_discovery_rpc.sql:55-101`); the screen renders “Nothing to verify nearby” (`verify.tsx:320-325`). Reproduced with installed `@tanstack/query-core`: `after first: 1 error`; immediate remount: `2 success []`. The cooldown test in `verifyFlow.test.tsx` covers Retry while mounted, not reopen. Preserve the error or defer automatic remount until cooldown expiry, and test this sequence with the cooldown-aware stand-in.

2. **C6, medium — a creator already viewing the Map can miss publication indefinitely.** `app/src/features/submit/useMySubmissionPublications.ts:49-57` has no interval, subscription, app-focus bridge, or screen-focus refetch. `app/src/app/(tabs)/index.tsx:119-122` reads only the cached result. The only other invalidation is an accepted verification by the *same* account (`app/src/features/verify/useVerify.ts:35-39`), while the publication is caused by another verifier. If the creator's Map query first returned `[]` and the Map stays mounted, no later fetch obtains the newly unseen row. `app/src/app/__tests__/(tabs)/MapScreen.test.tsx:256-305` seeds publication before the first render and misses this ordering. Add a bounded refresh on the next Map view or while it remains active and test empty-then-published. This is the D-68 fallback when push never arrives.

3. **C10, medium — queued design and summary contradict the built state.** The edited ERR-09 row still places the message *below* “I'm Here” (`docs/design/design-system.md:427`), while the error and Try Again render *above* the button (`app/src/app/(modals)/verify.tsx:571-605`); `.planning/phases/05-trust-engine-verification/05-03-SUMMARY.md:109` calls this a deviation. The summary also claims the filtered candidate list is “marked stale” (`:81-85`), while `app/src/features/verify/useVerify.ts:25-33` restamps it fresh, and its verification section still says 462 tests (`05-03-SUMMARY.md:112-115`) while the current suite has 467.
