### Findings

- [CRITICAL] `.claude/hooks/check-review-artifacts.js:578` - Check B reads `git diff --cached --name-only` as trimmed newline-delimited text. With Git's default `core.quotePath=true`, a protected staged name containing non-ASCII bytes is C-style quoted and prefixed with `"`; the resulting string no longer matches `^docs/` (or another protected prefix) and cannot equal the literal queue entry. I reproduced this in a fresh repository by staging an unqueued `docs/café.md`: Git printed `"docs/caf\303\251.md"` and the gate exited 0. This lets an unqueued protected file bypass the pre-commit review gate. The same parsing is used for policy-state deletions at line 593. Required fix: use `execFileSync('git', ['diff', '--cached', '--name-only', '-z', ...])`, split on NUL without trimming or unquoting, and add real-git regression tests proving unqueued non-ASCII (and preferably tab/newline-capable) protected paths and quoted policy deletions fail closed.
- [MAJOR] `.claude/hooks/check-review-artifacts.js:846` and `.claude/commands/codex-prompt.md:46` - The blind-review checker rejects any prompt containing the other reviewer's canonical verdict pathname, but the queued prompt command explicitly tells the generated packet to name that pathname, and the exact queued diff also embeds it. The current generated Codex and Antigravity packets therefore fail their own gate with “exposes the other reviewer verdict before blind review,” even when they only warn the reviewer not to read it. This makes the documented review flow unable to reach a passing commit gate for this scope. Required fix: reconcile packet generation and leakage detection so filenames/negative instructions and required source diffs do not count as verdict-content exposure, while actual reviewer output still does; add an end-to-end test that generates or fixtures the current cross-reviewer instructions and proves the gate accepts instructions but rejects embedded verdict content.
