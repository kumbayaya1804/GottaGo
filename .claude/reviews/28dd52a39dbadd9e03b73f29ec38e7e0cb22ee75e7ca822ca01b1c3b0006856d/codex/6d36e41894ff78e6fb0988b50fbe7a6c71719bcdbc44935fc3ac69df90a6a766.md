### Findings

1. **MAJOR — Announce the new error on iOS.** `app/src/app/gps-consent.tsx:131` supplies only `accessibilityLiveRegion="assertive"`. React Native 0.83.6 marks that property Android-only (`app/node_modules/react-native/Libraries/Components/View/ViewAccessibility.d.ts:237`). There is no iOS announcement or focus action in this screen. A VoiceOver user encountering a failed save therefore does not receive the required assertive error announcement; the tests merely find rendered text. This violates the new ERR-12 contract at `docs/design/design-system.md:430`. Add an iOS-supported announcement mechanism, covering initial and repeated retry failures, and verify it with platform-aware tests and VoiceOver. The platform distinction is also documented in the [official React Native accessibility source](https://github.com/react/react-native-website/blob/main/docs/accessibility.md).

2. **MAJOR — Make ERR-12 readable in light mode.** `app/src/app/gps-consent.tsx:80` and `app/src/app/gps-consent.tsx:87` combine `primarySurface` with `errorRed` at 15pt regular. Current light tokens are #E8F0FE and #EA4335 (`app/src/constants/Colors.ts:19`, `app/src/constants/Colors.ts:66`); their computed contrast is **3.4237:1**, below the **4.5:1** requirement at `docs/design/design-system.md:581`. Dark mode passes at 4.8151:1. The newly added matrix row locks in the failing combination, so revise both the ERR-12 treatment and implementation to use a compliant token combination, then check both themes. This affects the recovery instructions precisely when the user needs them.
