### Findings

- **[MAJOR] `.claude/hooks/check-review-artifacts.js:115-162, 603` — Commit authorization still depends on mutable working-tree trust inputs rather than the staged bytes being committed.** `readPolicy()` and `readRepoJson()` use `fs.readFileSync`, and the canonical packets/verdicts are also loaded through `readFileSafe()` from the worktree. An unstaged policy, contract, calibration receipt, packet, or verdict can therefore govern whether different staged bytes are accepted. The queue hash protects queued payload bytes, but it does not bind these enforcement inputs to the index. Required fix: read commit-gating inputs from the index, or fail closed whenever each trust input's clean-filtered working-tree blob OID differs from its staged blob OID; add an integration test that stages a restrictive input, weakens only the worktree copy, and proves the commit gate rejects it.

- **[MAJOR] `.claude/hooks/check-review-artifacts.js:201-237, 319-330` and `.claude/antigravity-calibration-contract.json:3-13` — Calibration truth remains self-certified instead of derived from hidden expected outcomes.** The hook trusts header `falseApprovals`, skips any row not marked `passed: true`, and counts author-supplied `passed` values. Binding a passing row to an `ADVISORY` archive proves only that a clean token was emitted; it does not prove the canary defect was detected or that the verdict matched the withheld expected result. A hand-authored evidence file can label rows passed and report zero false approvals without the gate independently deriving either fact. Required fix: introduce a trusted case manifest or runner-owned result artifact with hidden expected outcomes, bind every run to its case input and verdict archive, derive pass/fail and false-approval counts from the expected-versus-observed result, and test forged `passed`/`falseApprovals` values.

- **[MAJOR] `.claude/hooks/check-review-artifacts.js:393-422` — Blind-review path detection is bypassable with CommonMark character references.** `canonicalizePathText()` decodes `%XX` forms but does not decode HTML/numeric character references. Executing the real staged function returned `true` for a literal archive path but `false` for both `[other](&#46;claude&#47;reviews&#47;<scope>&#47;antigravity&#47;x&#46;md)` and the equivalent `&period;`/`&sol;` form. CommonMark resolves character references in link destinations, so the packet can render a usable other-reviewer archive link while the gate accepts the raw source. Required fix: decode CommonMark numeric and named character references before path normalization, compose it to a fixed point with percent decoding, and add real-hook regression tests for decimal, hexadecimal, named, and mixed nested encodings. Authority: [CommonMark specification, links and character references](https://spec.commonmark.org/spec).
