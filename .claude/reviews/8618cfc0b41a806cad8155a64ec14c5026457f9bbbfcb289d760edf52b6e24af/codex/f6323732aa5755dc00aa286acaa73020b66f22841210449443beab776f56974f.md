### Findings

- **[MAJOR] `.claude/settings.json:8`** — All five commands use `node "$CLAUDE_PROJECT_DIR/..."` without `args` or an explicit shell. Claude Code's [hook reference](https://code.claude.com/docs/en/hooks) says the default on Windows without Git Bash is PowerShell and specifically warns that bare `$CLAUDE_PROJECT_DIR` is an undefined local variable there. The resulting script path is wrong; every hook fails to start, including `queue-edit`. The static test at `.claude/hooks/harness-hooks.test.js:361` asserts this broken string rather than Windows dispatch. Use exec form (`command: "node"`, `args: ["${CLAUDE_PROJECT_DIR}/.claude/hooks/harness-hooks.js", "queue-edit"]`, etc.) and cover dispatch in Windows CI.
- **[MAJOR] `.claude/hooks/harness-hooks.js:113`** — `toRepoRelative` accepts unnormalized relative and absolute-prefix remainders. Local calls returned `a/../../outside.txt` for relative input, the same for `/tmp/review-root/a/../../outside.txt`, and `other.txt` for `/tmp/REVIEW-ROOT/other.txt` with root `/tmp/review-root`. The latter can be a different directory on Linux. It returns `null` for a worktree file while `CLAUDE_PROJECT_DIR` remains the main checkout; [Claude Code documents](https://code.claude.com/docs/en/hooks) that this variable stays at the original root while hook-input `cwd` follows a worktree. `queueEdit` at line 165 exits 0 without queueing. Resolve the affected checkout from hook input, canonicalize paths, enforce containment with platform-aware case semantics, and test traversal, case-sensitive siblings, and worktrees.
- **[MAJOR] `.claude/hooks/harness-hooks.js:199`** — `--` prevents Git option injection but does not make following arguments literal pathspecs. In a disposable Git repository, a queue containing only `*.txt` made `stage-queue` exit 0 and stage `one.txt`, `two.txt`, and `.claude/review-queue.txt`. This violates the exact-queue claim and widens the staged scope. Git's [pathspec reference](https://git-scm.com/docs/gitglossary) defines glob and magic parsing. Use literal pathspec handling and test names containing `*`, `?`, and `:(...)`.
- **[MINOR] `.claude/hooks/harness-hooks.js:184`** — `beadsOrFallback` treats a present `bd` exiting nonzero as success: `main` exits 0 with no recovery pointer. Propagate the failure or emit an actionable fallback and test a failing `bd`. `stdio: 'inherit'` passes hook stdin to `bd`; interactive behavior remains unverified.
- **[MINOR] `scripts/os-portability.test.js:47`** — The active-doc scan misses `NPM.CMD`, `C:/Users/...`, and `/Users/<name>/...`; generated latest packets are excluded despite being active review inputs. Tighten scope and patterns if this is meant to enforce the documented cross-OS guarantee.
