### Findings

- [MAJOR] `.claude/hooks/check-review-artifacts.js:115` - The policy and calibration trust inputs are read from working-tree files, not from the Git index whose commit is being authorized. An unstaged edit can therefore set `mode: disabled`, lower the evidence floor, turn off blind/archive enforcement, or point at different calibration data while the commit retains different policy bytes. The real-git tests currently normalize this behavior: `createRepo()` writes an untracked active policy/calibration bundle, and `passes when queued scope and all required artifacts agree` accepts it. Load the policy, contract, evidence, prompts, and calibration archives from the index, or fail on any worktree/index mismatch, and add a fixture proving an unstaged weakened policy cannot affect a staged commit.

- [MAJOR] `.claude/hooks/check-review-artifacts.js:189` - Calibration is still semantically self-certifying. `passed`, `falseApprovals`, `model`, `command`, `timestamp`, and `runId` are trusted strings/booleans; an archive needs only a content-addressed filename, a `VERDICT:` line, and the case ID. Nothing binds the verdict to the declared prompt hash or derives whether the hidden canary was detected. The passing `writeCalibration()` fixture demonstrates this: it never runs its recorded command or a reviewer, yet the hook grants active authority. Derive pass/fail and false approvals from a case manifest plus the archived verdict, bind each archive to its prompt hash/run identity, and retain the evidence bundle in the index.

- [MAJOR] `.claude/hooks/check-review-artifacts.js:361` - Blind-output detection remains bypassable with ordinary URI encoding. Direct execution of the staged function detected `.claude%2freviews/.../antigravity/...`, but returned `false` for `%2eclaude%2freviews/.../antigravity/...` and for `.claude%252freviews/.../antigravity/...`. Those are usable encoded references after URI decoding, so a packet can still expose the other verdict while passing `blind_review: true`. Canonicalize percent-encoded path characters comprehensively and repeatedly to a bounded fixed point, then add full-hook fixtures for encoded dots, encoded filename punctuation, and nested encoding.

- [MAJOR] `.beads/context/execution-state.md:16` - The task's active state and stale-scan fixes are staged but excluded from the 18-file queue and `scope_hash`, despite being material claims in this review. Worse, execution state says Round 3 is recorded in `.planning/STATE.md`, while `.planning/STATE.md:74` still ends this workstream at “Round-2 review not yet run.” The stale scan also claims the active state documents are current. Queue and fingerprint the task-related state/scan files (or remove them from this commit), reconcile the round history, and regenerate both packets/verdicts so later edits cannot preserve a stale approval.

- [MAJOR] `.claude/hooks/check-review-artifacts.js:326` - The new index-byte equality check breaks a legitimate Windows archive flow under this repository's `core.autocrlf=true`. `archive-review-artifact.js` hashes and writes working-tree text, while `git add` may normalize a CRLF verdict to LF in the index; `indexContent(archivePath) === content` then fails forever even though the archiver staged the file it wrote. A direct Git filter probe against an archive path produced different raw and filtered blob IDs. Define archive paths as binary (`-text`) or hash/compare the canonical index bytes, and add a CRLF regression fixture.

- [MINOR] `.claude/hooks/check-review-artifacts.js:236` - The staged JavaScript contains a literal NUL byte in the `(caseId, runId)` separator. Node accepts it, but `rg` treats the entire enforcement script as binary, suppressing normal line-oriented audit searches. Replace it with the source escape `'\0'` (two printable source characters) and add a text-file/source-hygiene assertion.
