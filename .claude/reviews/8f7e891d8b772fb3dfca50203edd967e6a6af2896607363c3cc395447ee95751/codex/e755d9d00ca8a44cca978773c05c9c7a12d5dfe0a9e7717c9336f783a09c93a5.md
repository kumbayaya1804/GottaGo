1. **MAJOR — An empty pending snapshot disables the only in-session publication refresh.** `app/src/app/(tabs)/index.tsx:111-126` fetches pending submissions once and treats a successful empty answer as lasting. At `index.tsx:134` that turns polling off; `app/src/features/submit/useMySubmissionPublications.ts:63-68` removes the interval. A user can leave this Map open after an empty result, create a pending submission on another device, and have it published by others. Neither query has a remote update path, so this mounted Map never shows “Published!”. The guard test at `app/src/app/__tests__/(tabs)/MapScreen.test.tsx:453-467` confirms that three intervals make no second unseen-publication call after an empty pending result. This contradicts packet claims C6 and C11 and weakens the D-68 in-app fallback. Keep an unseen-publication discovery path after an empty pending snapshot, and test publication arriving later.
