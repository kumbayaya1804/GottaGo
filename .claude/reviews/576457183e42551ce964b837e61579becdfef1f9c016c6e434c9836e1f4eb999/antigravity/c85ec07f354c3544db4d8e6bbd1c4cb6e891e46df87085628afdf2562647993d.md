### Concerns
- Pipeline segment splitting in packet scanner: `referencesUnsafeFullGateInvocation` splits lines into segments at `;`, `&&`, `||`, `|`, and `.\s`. If a command places the gate path and the runtime on opposite sides of a pipe (e.g. `cat .claude/hooks/check-review-artifacts.js | node` or `echo .claude/hooks/check-review-artifacts.js | xargs node`), the first segment contains `check-review-artifacts.js` preceded only by `cat` or `echo` (neither in `runtimeWord`), and the second segment contains `node` with no gate token. Both segments pass `runsGateInSegment`, returning `false`. This, alongside multi-line command splitting, is accurately disclosed in `docs/agent-harness.md` Known Limitations. Reviewer independence ultimately relies on workflow rules in `.claude/skills/review_packet_generator.md` and pre-commit enforcement of `prior_reviewer_outputs_read: false`.
- `PostToolUse` non-blocking failure: Per official Claude Code documentation (https://code.claude.com/docs/en/hooks), `PostToolUse` hooks emit stderr on non-zero exit but do not abort tool calls. If `harness-hooks.js queue-edit` throws or fails to spawn on an unqueued edit, the file is modified on disk but omitted from `.claude/review-queue.txt`. This risk is mitigated by Check B in `.beads/hooks/pre-commit` (`check-review-artifacts.js`), which fails closed on any staged review-required file not in the queue.

### Adversarial Disproof
- Premise 1: Option flags with arguments evade segment scanner.
  - Tested: `node -r fs .claude/hooks/check-review-artifacts.js` and `node --inspect=0 .claude/hooks/check-review-artifacts.js`.
  - Result: Both returned `true` (blocked). Matching `runtimeWord.*?\S*gateToken` within the segment eliminates reliance on flag grammar.
- Premise 2: Shell positional wrappers evade scanner.
  - Tested: `sh -c 'node "$0"' .claude/hooks/check-review-artifacts.js`.
  - Result: Returned `true` (blocked). `sh` is a runtime word appearing before the gate path in the segment.
- Premise 3: Extra trailing arguments on fingerprint command evade detection.
  - Tested: `node .claude/hooks/check-review-artifacts.js --print-staged-scope-hash --extra`.
  - Result: Returned `true` (blocked). `safeInvocation` lookahead `(?=\s*($|[;|&),.:]))` requires the fingerprint flag to terminate the command or segment.
- Premise 4: Scanner false-positive on prose naming runtime words across sentences.
  - Tested: `'Blocked forms include node and bash. The scanner lives in check-review-artifacts.js.'`.
  - Result: Returned `false` (allowed). The period followed by space (`.\s`) splits the sentences into distinct segments, avoiding false positive.
- Premise 5: Segment separator evasion via pipes.
  - Tested: `cat .claude/hooks/check-review-artifacts.js | node` and `echo .claude/hooks/check-review-artifacts.js | xargs node`.
  - Result: Both return `false` (evades segment scanner because runtime and target are on opposite sides of `|`). Confirmed as an out-of-model pipeline boundary and documented under Concerns and `docs/agent-harness.md`.
