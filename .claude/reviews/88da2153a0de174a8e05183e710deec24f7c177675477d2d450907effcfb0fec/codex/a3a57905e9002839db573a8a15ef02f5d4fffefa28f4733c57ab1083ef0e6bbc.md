On the local database with this migration installed, `length(btrim(chr(9)))` and `length(btrim(chr(10)))` both returned 1. In a transaction, I inserted a fixture user, set its JWT claims, switched to SQL role `authenticated`, and called `public.submit_location(chr(9), 44.05, -123.09, 10, false, now(), 'chill_spot')`: it returned a non-null UUID and staged one row whose name was a tab. The transaction was rolled back; the command exited 0. The publish path copies `s.name` unchanged to `public.locations` at migration line 325. Thus claim C4's blank-name rejection is false and a blank label can reach discovery. The new SQL test at `supabase/tests/phase5_rpc_input_validation.test.sql:93-104` covers NULL and spaces only. Reject all whitespace-only names at the server and add an authenticated-role regression for tabs/newlines or an equivalent counterexample. This serves the 60-second user by keeping unusable labels out of results.
