On installed Claude Code 2.1.283, the matcher `Write|Edit|MultiEdit` contains only exact-list characters, so it is evaluated as three exact tool names; `Edit` is not an unanchored substring match for `NotebookEdit`. The production comment and test incorrectly model the setting with `new RegExp(...)`, so the test passes without exercising Claude Code's matcher semantics. A notebook edit can therefore complete without invoking `queue-edit`, without adding the notebook to `.claude/review-queue.txt`, and without producing a hook failure. Required fix: explicitly include `NotebookEdit` in the exact alternative list (for example, `Write|Edit|MultiEdit|NotebookEdit`) and replace the self-authored regex oracle with a test that enforces Claude Code's documented exact-list semantics or a live dispatcher test. Official authority: https://code.claude.com/docs/en/hooks#matcher-patterns.
