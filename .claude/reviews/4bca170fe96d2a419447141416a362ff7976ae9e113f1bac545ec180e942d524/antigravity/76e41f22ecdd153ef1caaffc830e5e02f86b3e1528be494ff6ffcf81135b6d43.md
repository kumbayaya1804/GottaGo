### Concerns
- `fs.realpathSync.native` relies on libuv's `uv_fs_realpath`, which on Windows calls `GetFinalPathNameByHandleW(handle, ..., VOLUME_NAME_DOS)`. In libuv `src/win/fs.c` (`fs__realpath_handle`), libuv explicitly checks for `LONG_PATH_PREFIX` (`\\?\`) and strips 4 characters (`w_realpath_ptr += 4`), and converts `\\?\UNC\` to `\\`. It returns standard DOS drive-letter format (e.g. `C:\...`) with canonical case and expanded 8.3 short names.
- If a target or ancestor path lacks permissions or resides on an exotic filesystem that bypasses the Volume Manager, `GetFinalPathNameByHandleW` may return `ERROR_INVALID_HANDLE`. In `realpathOfExisting`, this error is caught in the `try...catch` loop, which gracefully walks up to the deepest accessible ancestor and falls back to `path.resolve(target)` at root.
- In Test 110, git on Windows outputs CRLF warning messages containing the filename. The regex `/^\s*PWNED\b/m` properly distinguishes between shell stdout (lines beginning with `PWNED`) and Git diagnostic messages (where the filename appears mid-line in quotes), while preserving the critical assertion that git literally staged the tricky path without command execution.
