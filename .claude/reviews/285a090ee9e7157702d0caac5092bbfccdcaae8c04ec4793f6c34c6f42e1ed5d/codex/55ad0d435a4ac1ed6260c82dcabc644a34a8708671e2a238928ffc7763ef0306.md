### Findings

- **[MAJOR] `.claude/hooks/check-review-artifacts.js:223` - Calibration remains self-asserted and can restore Antigravity approval authority without any qualifying run.** `validateCalibration()` checks that receipt-shaped strings exist and that `verdictArchive` names a content-addressed file, but it never binds the archive content or scope to `caseId`, `runId`, `model`, `promptSha256`, command, timestamp, or outcome. It also trusts the top-level `falseApprovals` value and permits every row to reuse one archive. In a real temporary Git repository, I supplied all five required cases and two distinct run IDs per case, pointed all ten rows at one unrelated content-addressed file containing only `this is not a verdict...`, set the commands to `never executed`, and the gate exited 0 in active mode. This preserves the round-1 authority-escalation flaw behind more fields. Require a unique, semantically bound receipt per `(caseId, runId)`; verify the prompt bytes against `promptSha256`; verify the archive is an Antigravity calibration verdict for the declared case/run/scope and contains a parseable outcome; derive independent-run and false-approval counts from those verified receipts; and add regressions for one reused archive, an unrelated-scope archive, a non-verdict archive, and mismatched prompt/result metadata.

- **[MAJOR] `.claude/hooks/check-review-artifacts.js:268` and `.claude/hooks/archive-review-artifact.js:24` - Untracked archive files satisfy the pre-commit gate, so the promised audit history need not enter the commit.** `hasArchivedCopy()` checks only `fs.existsSync()` and byte equality in the working tree. The archiver writes the file but never stages it. The existing passing fixtures likewise archive verdicts without adding them to the index. My isolated reproduction passed the gate while `git diff --cached --name-only` contained only `docs/example.md`; both verdict archives were present but untracked. The current scope directory is also reported as `?? .claude/reviews/285a.../`, contradicting `docs/agent-harness.md:58-60` and `.planning/stale-info-scan-latest.md:18`, which say archives are committed audit history. Require the exact archive blob to be present byte-for-byte in the Git index (or already tracked at the same blob) before the gate passes. Either have the explicit archiver command stage its newly created path or require a separate `git add`, and add tests proving an untracked archive blocks while an indexed archive passes.

- **[MAJOR] `.claude/hooks/check-review-artifacts.js:291` - Blind-review output detection is still bypassable with filesystem-equivalent path formatting.** `referencesReviewerOutput()` converts backslashes and lowercases text but does not collapse repeated separators or normalize `.`/`..` segments. After appending `See .claude//reviews/<current-scope>/codex/fake.md` to an otherwise valid Antigravity packet in an isolated repository, the gate still exited 0 even though that path resolves to the other reviewer's archive directory. This disproves the packet's blind-review enforcement claim and answers its doubled-separator open question. Canonicalize candidate paths before comparison, or use a matcher that accepts repeated/mixed separators and dot segments; safely consider percent-decoded path forms where the packet consumer resolves them. Add adversarial tests for doubled separators, `./`, `../`, mixed separators/case, and encoded separators.

- **[MINOR] `.claude/hooks/check-review-artifacts.test.js:761` and `.planning/stale-info-scan-latest.md:12` - The recorded zero-skip suite result is not reproducible on this Windows host even though Git Bash is installed.** The test searches only `where sh`; `sh.exe` exists at `C:\Program Files\Git\bin\sh.exe` but is not on `PATH`, so the fresh suite result was 38 pass / 1 skipped, not 39 pass / 0 skipped. I separately executed that shell, confirmed `sh -n` succeeds, and confirmed the wrapper exits 1 when its child PATH cannot resolve Node. Make the test resolve common Git-for-Windows shell paths (or explicitly configure the test environment), then update the saved evidence to the observed result.

- **[MINOR] `.beads/context/execution-state.md:13` and `.planning/stale-info-scan-latest.md:58` - Active state still claims `app/src/lib/database.types.ts` is staged and awaiting review after this packet explicitly unstaged it.** Fresh `git status --short` reports it as worktree-only (` M`), while the latest scan says the active state documents accurately describe the current Phase 5 state.
