### Findings

1. **Medium — the new visible-character rule accepts control-only names.** The exclusion lists at `supabase/migrations/20261016010000_phase5_submission_name_hardening.sql:73` and `app/src/features/submit/submitSchema.ts:27` omit control characters including U+0001 (C0), U+007F (DEL), and U+0080 (C1). U+0001 survives JavaScript `trim()`, matches `VISIBLE_CHAR`, and has length 1. In a disposable PostgreSQL instance with this migration applied, an authenticated-role call to `public.submit_location(chr(1), ...)` returned a submission UUID; the transaction was rolled back. This defeats the stated requirement for at least one visible character and can stage a location without a readable label for someone searching urgently. Add the omitted nonprinting controls to both rules and regression cases to the SQL and form tests (`supabase/tests/phase5_submission_name_hardening.test.sql:25`, `app/src/features/submit/__tests__/submitSchema.test.ts:34`). The all-code-point drift test at `app/src/features/submit/__tests__/submitSchema.test.ts:75` proves agreement between two lists, but cannot show that either list defines visibility correctly.
