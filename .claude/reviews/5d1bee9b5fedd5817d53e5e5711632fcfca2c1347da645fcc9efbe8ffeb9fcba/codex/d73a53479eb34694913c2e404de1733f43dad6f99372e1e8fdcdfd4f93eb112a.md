### Findings

- **MEDIUM — Restore the submitted name's 120-character limit.** `app/src/features/submit/submitSchema.ts:21` trims before `.max(120)`, so 121 spaces plus `A` passes validation as `A`. The screen uses `trigger()` to advance and later calls `buildInput(getValues(), ...)` at `app/src/app/(tabs)/submit.tsx:227`. Installed React Hook Form's `trigger()` updates errors but `getValues()` returns raw form values (`app/node_modules/react-hook-form/dist/index.esm.mjs:1734-1754,2123-2177`). Thus `submitLocation.ts:23` sends the original 122-character name, and SQL stores `p_name` unchanged at `supabase/migrations/20261016000000_phase5_rpc_input_validation.sql:466-475`. A local Zod reproduction returned `{ "rawLength":122, "accepted":true, "parsedLength":1 }`. The prior untrimmed `.max(120)` rejected this input. The new screen test covers only spaces-only input. Enforce the limit on the value actually submitted and test a padded overlength name along the caller path. Arbitrarily padded names can reach pending and published map records, degrading names shown to urgent users.
