### Findings

- **[MAJOR] `.claude/hooks/harness-hooks.js:216`** — The PostToolUse matcher in `.claude/settings.json:14` is `Write|Edit|MultiEdit`. Claude Code's [matcher documentation](https://code.claude.com/docs/en/hooks) says regex matching succeeds anywhere in a tool name, so `NotebookEdit` matches `Edit`. `NotebookEdit` supplies `tool_input.notebook_path`, while `queueEdit` reads only `file_path` and returns 0 at line 217. A synthetic `NotebookEdit` payload against the CLI exited 0 without creating a queue. This silently omits a successful notebook change, including one outside the pre-commit gate's protected paths. Handle `notebook_path` and test this matched tool, or explicitly exclude it and provide an equivalent queue path.
- **[MAJOR] `.claude/hooks/harness-hooks.js:59`** — Case sensitivity is inferred from the OS, not the filesystem. On this macOS host `CASE_INSENSITIVE_FS` is true and `toRepoRelative('/tmp/REVIEW-ROOT/other.txt', '/tmp/review-root')` returns `other.txt`. [Apple documents](https://developer.apple.com/documentation/technologyoverviews/files-and-directories) that macOS APFS can be case-sensitive. On such a volume those are different directories, so an outside edit can be queued as an inside path. Use canonical filesystem containment that works for both APFS variants, and test the case-sensitive macOS condition rather than hard-coding Darwin to insensitive.
- **[MINOR] `.claude/hooks/harness-hooks.js:231`** — A worktree edit is now queued in the worktree, but `stop-review-queue` still reads the `CLAUDE_PROJECT_DIR` main checkout queue. In a disposable real-Git worktree with only its queue populated, the Stop command exited 0 with no reminder. Route the reminder to the active checkout's queue and add a worktree Stop test.
