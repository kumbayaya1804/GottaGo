### Adversarial Disproof
- **Premise 1**: Does `toRepoRelative` still accept backtracking relative paths like `a/../../outside.txt`?
  - **Counterexample attempted**: `toRepoRelative('a/../../outside.txt', '/repo')`.
  - **Outcome**: Retained. `path.posix.normalize` normalizes the input to `'../outside.txt'`, which fails the containment check (`relative.startsWith('../')`) and returns `null`.
- **Premise 2**: On a case-sensitive filesystem (Linux), does `toRepoRelative` still treat a directory differing only by case as inside the root?
  - **Counterexample attempted**: `toRepoRelative('/tmp/REVIEW-ROOT/other.txt', '/tmp/review-root', { caseInsensitive: false })`.
  - **Outcome**: Retained. Returns `null` when `caseInsensitive` is false (the default on Linux).
- **Premise 3**: Can glob characters or `:(magic)` pathspecs in queued file names cause `stage-queue` to stage unintended files?
  - **Counterexample attempted**: Tested `stageQueue` with `*.txt`, `?ne.txt`, `:(glob)*.txt`, and `:(top)one.txt`.
  - **Outcome**: Retained. `git --literal-pathspecs add -A -- <paths>` treats pathspecs literally; non-existent literal glob filenames cause git to fail with exit 128 without staging any matching files.
- **Premise 4**: Can a failing `bd` subprocess block Claude Code hooks by attempting to read stdin?
  - **Counterexample attempted**: Tested `session-start` and `pre-compact` with a simulated `bd` script that invokes `read line`.
  - **Outcome**: Retained. `stdio: ['ignore', 'inherit', 'inherit']` detaches stdin; `bd` cannot read hook payloads or block on input, and the hook emits the fallback pointer message naming the non-zero exit code.

### Runtime Boundary Check
- **Exec Form Process Dispatch**: In `.claude/settings.json`, hooks are declared as `{"type": "command", "command": "node", "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/harness-hooks.js", "<cmd>"]}`. This eliminates the shell boundary entirely: Claude Code executes `node` directly with arguments, substituting `${CLAUDE_PROJECT_DIR}` without shell tokenization or quoting vulnerabilities.
- **Git Worktree Isolation**: `queueEdit` determines the appropriate queue destination by checking worktree roots via `git rev-parse --path-format=absolute --git-common-dir`. Edits inside a project worktree are queued in that worktree's own `.claude/review-queue.txt`, avoiding pollution of the main repository queue while verifying common git ancestry to prevent writing into unrelated foreign repositories.
- **Fail-Closed Review Backstop**: Pre-commit hook (`.beads/hooks/pre-commit`) and gate script (`check-review-artifacts.js`) enforce that any staged protected file must appear in `.claude/review-queue.txt`, ensuring that even if a hook fails to run, unreviewed protected code cannot be committed.
