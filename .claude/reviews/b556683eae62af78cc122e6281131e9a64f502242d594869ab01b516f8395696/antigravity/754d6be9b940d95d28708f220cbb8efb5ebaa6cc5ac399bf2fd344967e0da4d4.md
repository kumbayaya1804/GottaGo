### Issues
- [MINOR] .claude/hooks/check-review-artifacts.js:547 - Full-gate detector regex lookahead treats terminal period as path continuation: In `referencesUnsafeFullGateInvocation`, `anyInvocation` uses negative lookahead `(?![\w./-])`. If an instruction or prompt ends with `node .claude/hooks/check-review-artifacts.js.` (where the script name is unquoted and immediately followed by a sentence-ending period without trailing space), the lookahead matches `.` and considers it a path extension, returning `false` (undetected). Tested via probe: `referencesUnsafeFullGateInvocation("Run node .claude/hooks/check-review-artifacts.js.") === false`. While Node itself rejects `check-review-artifacts.js.` as `MODULE_NOT_FOUND`, a human or agent reading the instruction would execute the script without the period. Impact: does not break production or pre-commit; this is a narrow evasion surface in the heuristic packet scanner. Recommendation for future hardening: distinguish path characters from sentence-ending punctuation or strip trailing periods before matching.

### Concerns
- `PostToolUse` non-blocking failure: Per official Claude Code documentation (https://code.claude.com/docs/en/hooks), `PostToolUse` hooks emit stderr on non-zero exit but do not abort tool calls. If `harness-hooks.js queue-edit` throws or fails to spawn on an unqueued edit, the file is modified on disk but omitted from `.claude/review-queue.txt`. This risk is mitigated by Check B in `.beads/hooks/pre-commit` (`check-review-artifacts.js`), which fails closed on any staged review-required file not in the queue.
- Regex evasion vectors in packet heuristic: Indirection such as environment variables (`SCRIPT=...; node $SCRIPT`), directory changes (`cd .claude/hooks && node check-review-artifacts.js`), or package runners (`npx`) bypass `referencesUnsafeFullGateInvocation`. The workflow rules in `review_packet_generator.md` and manual reviewer instructions are the true boundary against premature full-gate runs during blind review.
