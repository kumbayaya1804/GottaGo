### Concerns
- Conservative prose blocking in packet scanner: Because `referencesUnsafeFullGateInvocation` operates line-wide and order-independently, any single line in a review packet or prompt that mentions both the gate script name (`check-review-artifacts` or `check-review-artifacts.js`) and any runtime/shell word (`node`, `sh`, `bash`, `exec`, etc.) is flagged as unsafe, even in non-executing explanatory text. Packet authors must reword such prose (e.g. splitting into separate lines or referring to "the gate script"). This tradeoff is accurately documented in `docs/agent-harness.md` Known Limitations.
- Out-of-model scanner boundaries: Multi-line commands (where arguments or continuation characters span newlines) or executions that never spell the gate name (globs, variable substitutions, computed strings) remain out of the heuristic scanner's per-line model. Reviewer independence is backstopped by the gate CLI argument check (refusing unknown flags with exit 2 before inspection) and the requirement that reviewers declare `prior_reviewer_outputs_read: false`.
- `PostToolUse` non-blocking failure: Per official Claude Code documentation (https://code.claude.com/docs/en/hooks), `PostToolUse` hooks emit stderr on non-zero exit but do not abort tool calls. If `harness-hooks.js queue-edit` throws or fails to spawn on an unqueued edit, the file is modified on disk but omitted from `.claude/review-queue.txt`. This risk is mitigated by Check B in `.beads/hooks/pre-commit` (`check-review-artifacts.js`), which fails closed on any staged review-required file not in the queue.
